# Web Designer

Design browser pages, dashboards, prototypes, HTML slides, visualizations, and UI motion. Pure logic changes, content-only conversion, standalone image generation, and narration-led video production are outside this skill.

## Working principles

- Use the project's stack, supplied references, and existing design system. Preserve behavior, content, and public contracts outside the requested changes.
- Make hierarchy, density, imagery, and motion serve the audience and task. Examples are starting points; legibility and accessibility take precedence.
- Clarify gaps that materially affect the outcome. Continue independent work; label missing assets and sample data instead of inventing brand assets or factual claims.
- Match exploration and verification to the change. Drafts, variants, controls, and scores are useful when they resolve uncertainty; they are optional. Report what was actually checked.
- Without a supplied direction, don't fall back on default styles: cream or off-white grounds, italic accent words in headlines, numbered "01/02/03" section labels, monospace eyebrow labels, and pill-shaped buttons. Use them only when the brief, brand, or chosen reference calls for them.

## Read only when needed

Handle small, clear visual changes directly. Select references by the decision at hand; links are not a reading sequence. Basic verification may use inspection or a targeted browser preview without loading an acceptance workflow.
